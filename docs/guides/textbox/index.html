Dal browser all’applicazione

Dentro textBox

Come un normale input diventa un componente Gramlot. Un passo alla volta, senza dare per conosciuti i Web Components.

Seguiremo un solo campo di testo: prima l’elemento nativo, poi il suo involucro, infine il collegamento con Python e con i dati della pagina.

Lettura guidata · 14 capitoli · circa 25 minuti
Codice di riferimento: Gramlot 0.1.5 locale · 14 settembre 2026

01 · Il punto di partenza: un campo di testo

Un campo in cui scrivere sembra un oggetto semplice. Per capirlo partiamo dalla parte che il browser sa già costruire: <input type="text">. Il browser fornisce cursore, selezione del testo, tastiera, copia e incolla. Gramlot conserva questo lavoro.

HTML descrive gli elementi della pagina. Un tag è un nome tra parentesi angolari; un attributo è un’opzione scritta nel tag. placeholder mostra un suggerimento quando il campo è vuoto. Un’etichetta visibile dice a che cosa serve il campo, anche dopo che abbiamo iniziato a scrivere.

HTML Esempio didattico
<label for="nome">Nome</label>
<input id="nome" type="text" placeholder="Scrivi il nome">

Il browser trasforma questo testo in oggetti collegati tra loro: il DOM, cioè l’albero degli elementi della pagina. JavaScript può leggere e modificare questi oggetti. CSS stabilisce il loro aspetto.

Il campo HTML nudo non conosce una Data Bag, un percorso come persona.nome o il significato di ^. La digitazione cambia il valore del campo; il collegamento ai dati dell’applicazione è un altro compito.

02 · Che cosa vogliamo riutilizzare

In un’applicazione non serve soltanto una casella. Vogliamo un’etichetta allineata, stato disabilitato, sola lettura, messaggi di errore, un comportamento coerente quando arriva un nuovo valore e una regola precisa su quando salvare ciò che l’utente scrive.

Se ricostruiamo ogni volta questi dettagli, ogni campo può comportarsi diversamente. Un componente li mette a disposizione attraverso un’interfaccia: chi lo usa sceglie i parametri; chi lo implementa gestisce l’interno.

ResponsabilitàChi la svolge nel textBox attuale
Scrivere, selezionare e modificare testoIl controllo HTML nativo
Esporre valore, etichetta e stati del campoIl Web Component e le basi condivise
Collegare il campo a un percorso datiIl runtime Gramlot
Descrivere l’interfaccia dell’applicazioneIl codice Python o JavaScript dell’autore

03 · Che cos’è un Web Component

Possiamo insegnare al browser un nuovo nome di elemento. Per esempio <demo-textbox> può indicare una nostra classe JavaScript. La classe è la definizione del comportamento; ciascun elemento presente nella pagina è un’istanza distinta.

Custom Element significa proprio elemento personalizzato. Una classe deriva da HTMLElement, la base degli elementi HTML, e viene registrata con customElements.define. I nomi personalizzati contengono un trattino. La registrazione dice al browser quale classe usare per quel tag. Approfondimento: custom elements.

“Web Components” è il nome di un insieme di funzionalità del browser. Qui ci interessano soprattutto gli elementi personalizzati e lo Shadow DOM. Template e slot sono strumenti aggiuntivi; non sono un passaggio obbligatorio per capire questo campo.

JavaScript Esempio didattico
class DemoTextBox extends HTMLElement {
  constructor() {
    super(); // Inizializza la parte HTMLElement ereditata.
    const root = this.attachShadow({mode: 'open'});
    this._input = document.createElement('input');
    this._input.type = 'text';
    root.appendChild(this._input);
  }
}
customElements.define('demo-textbox', DemoTextBox);
HTML Esempio didattico
<demo-textbox></demo-textbox>
Questo è un passaggio didattico per chi implementa componenti. Non è ancora il textBox di Gramlot: mancano interfaccia pubblica, etichetta, eventi e integrazione con i dati. Nelle applicazioni Gramlot si dichiarano i componenti attraverso il framework.

04 · Dentro e fuori: lo Shadow DOM

Lo Shadow DOM è un albero interno collegato a un elemento. L’elemento esterno è chiamato host. Nel nostro esempio l’host è demo-textbox; dentro c’è l’input che riceve i tasti.

Pagina · DOM esterno
<gnr-textbox> host del componente reale
Shadow root · interno del componente
stile + contenitore dell’etichetta + contenuto
<label>Nome</label>
<input type="text"> qui si scrive davvero

Questa separazione aiuta a controllare struttura e stili. Un selettore CSS della pagina come input { … } non seleziona direttamente l’input dentro lo Shadow DOM. Alcuni valori ereditabili e le variabili CSS possono invece attraversare il confine.

mode: 'open' consente l’accesso tramite element.shadowRoot. Non è una misura di sicurezza: lo Shadow DOM organizza l’implementazione. Approfondimento: Shadow DOM.

Per chi scrive un’applicazione, entrare nell’albero interno per cambiare l’input crea una dipendenza dai dettagli del componente. In Gramlot si usano i parametri e i servizi pubblici; la manipolazione dell’input appartiene all’implementazione del componente.

05 · Il componente deve avere una porta di accesso

Aggiungere un input all’interno non basta. Il componente esterno deve spiegare come leggere e assegnare un valore. Una proprietà JavaScript è un valore accessibile su un oggetto, come campo.value. Un getter legge; un setter assegna.

JavaScript Esempio didattico
// Da aggiungere alla classe didattica DemoTextBox.
get value() {
  return this._input.value;
}
set value(value) {
  this._input.value = value == null ? '' : String(value);
}

Ora il chiamante può usare campo.value = 'Ada' senza sapere dove si trovi l’input. Questo setter semplificato mostra null come testo vuoto e non ne conserva la distinzione: il componente Gramlot reale gestisce anche quel caso.

Il confronto seguente usa il controllo HTML nativo. In un elemento personalizzato una proprietà come placeholder deve essere esposta esplicitamente: il solo attributo non la crea.

Attributo HTMLProprietà JavaScript
placeholder="Nome"input.placeholder = 'Nome'
Nel markup è testo o presenza/assenzaPuò contenere tipi JavaScript, anche oggetti
Non si sincronizza da solo con una proprietà personalizzataIl componente decide come leggerla e applicarla

Per gli attributi booleani la presenza conta: disabled="false" è comunque un attributo presente. Per riabilitare il controllo si rimuove l’attributo. Gramlot si occupa della traduzione dei valori dichiarati nell’applicazione.

Un componente può dichiarare observedAttributes; il browser chiama attributeChangedCallback quando uno di questi attributi cambia. Il textBox reale osserva value, placeholder, lbl, disabled e readonly nella base condivisa. Altri parametri sono gestiti dai servizi di Gramlot.

06 · Come una modifica esce dal componente

Un evento è una notifica: “è successo qualcosa”. Il controllo nativo produce input durante le modifiche dell’utente e change quando una modifica viene confermata. Assegnare una proprietà da codice non equivale a una digitazione e non emette automaticamente questi eventi.

Due parole descrivono il viaggio dell’evento: bubbles permette di risalire verso gli antenati; composed permette di attraversare un confine Shadow DOM. Sono due proprietà diverse.

Nella base Gramlot, l’evento nativo input attraversa già il confine. Il change interno viene riemesso sull’host, per raggiungere l’ascoltatore del runtime:

JavaScript Estratto reale · ControlElement
this._input.addEventListener('change', () => {
  this.dispatchEvent(new this.ownerDocument.defaultView.Event(
    'change', {bubbles: true, composed: true}
  ));
});

Per un ascoltatore esterno, la destinazione dell’evento proveniente dall’interno viene presentata come l’host: è il retargeting. Gramlot può così riconoscere il componente e leggere la sua proprietà value, senza cercare l’input nello Shadow DOM.

07 · Il textBox reale è piccolo perché eredita molto

Nel file collections/inputs.js la classe specifica è questa:

JavaScript Estratto reale · inputs.js
class GnrTextBox extends GnrInput { get inputType() { return 'text'; } }

Quella riga non contiene tutto il componente. GnrInput è il nome locale con cui il modulo usa ControlElement:

JavaScript Estratto reale · inputs.js
const {ControlElement: GnrInput} = getComponentBases();
LivelloCompito
HTMLElementLa base fornita dal browser
GramlotElementConnessione, disconnessione e rilascio delle risorse registrate
DecoratedCollega il servizio che presenta etichetta e contenitore
FieldStateEspone la presentazione degli stati del campo, per esempio errore e attesa
ControlElementCrea input e Shadow DOM, espone value, inoltra attributi ed eventi, gestisce null e decorazione
GnrTextBoxSceglie un input di tipo testo

Decorated e FieldState sono mixin: funzioni che ricevono una classe base e restituiscono una classe con una capacità aggiuntiva. L’espressione reale FieldState(Decorated(GramlotElement)) costruisce questa combinazione. Non occorre conoscerla per usare root.textBox; serve a chi mantiene il framework.

Il browser chiama connectedCallback quando un elemento entra nel documento e disconnectedCallback quando ne esce. La base evita di installare due volte la connessione attiva e rilascia i funzioni di pulizia (disposer) registrate con ownConnection. Un elemento può essere rimosso e reinserito: costruzione e connessione non sono sinonimi.

08 · Due registrazioni: browser e Gramlot

Il browser deve conoscere il tag; Gramlot deve conoscere il nome da usare nelle dichiarazioni. Sono due associazioni complementari.

JavaScript Registrazione nel browser
customElements.define('gnr-textbox', GnrTextBox);

Il catalogo attuale contiene questa descrizione, riportata integralmente per textBox:

JSON Descrizione reale · builtin-components.json
{
  "name": "textBox",
  "tag": "gnr-textbox",
  "subTags": "",
  "pythonGroup": "InputDeclarations",
  "capabilities": [
    "control",
    "decoration",
    "null",
    "field-state"
  ]
}

name è il nome dell’API di authoring; tag è il tag del browser. pythonGroup indica il gruppo di dichiarazioni Python da generare. subTags è vuoto: textBox non dichiara contenuto Source figlio. capabilities elenca capacità; non ne implementa il comportamento.

JavaScript Registrazione della collezione Gramlot
registerComponentCollection('inputs', {
  components: builtinComponents('inputs'),
  defineComponents
});

Il registro costruisce la grammatica e l’associazione render_tag, attiva la funzione che definisce gli elementi e verifica che i tag siano stati registrati. Associa inoltre la descrizione alla classe con gramlotComponent.

Limite attuale del manifesto: per textBox questa scheda contiene identità e capacità, ma non ancora una descrizione completa di parametri ed esempi. Questi capitoli ricostruiscono il contratto leggendo codice e test. Il documento non attribuisce al manifesto informazioni che oggi non contiene.

09 · Come si usa: Python prima di tutto

Chi scrive una pagina Gramlot non deve definire una classe JavaScript per ogni campo. Dichiara il componente sotto un nodo padre:

Python Pagina Gramlot · esempio completo di authoring
from gramlot.page import WebPage

class Page(WebPage):
    def main(self, root):
        root.data('nome', 'Ada')
        root.textBox(value='^nome', lbl='Nome',
                     placeholder='Scrivi il nome')
        root.div('^nome')

root è il punto in cui aggiungere gli elementi. data dichiara il dato iniziale. textBox aggiunge un nodo alla Source Bag. div mostra il valore dello stesso dato. Per eseguire la pagina occorrono l’host e il runtime Gramlot configurati; il frammento non avvia un server.

Una Bag è una struttura dati ad albero, con nodi identificati da nomi e percorsi. La Source Bag descrive la struttura della pagina. La Data Bag contiene lo stato dell’applicazione. Il binding ^nome collega il valore del campo a un percorso nella Data Bag e reagisce alle variazioni. Non è un identificativo HTML e non è il testo da mostrare.

La dichiarazione Python viene generata da scripts/generate_components.py. Per textBox il risultato include:

Python Dichiarazione generata · estratto riformattato
@element(sub_tags='', _meta={
    'webcomponent': True, 'render_tag': 'gnr-textbox'
})
def textBox(self, **kwargs): ...

I puntini non indicano che manca l’implementazione grafica: questo metodo dichiara un elemento della grammatica. Python costruisce il Source; il trasporto TYTX lo conserva per il browser; il runtime realizza il componente. **kwargs accetta opzioni: non significa che qualsiasi nome inventato acquisti un comportamento.

Un autore JavaScript usa lo stesso vocabolario, nel corpo della costruzione della pagina:

JavaScript Authoring Gramlot JS · con dati già inizializzati
root.textBox({value: '^nome', lbl: 'Nome'});

Il nome del componente resta textBox; il tag resta gnr-textbox. L’oggetto che coordina la pagina si chiama invece gramlot. Sono tre nomi con tre ruoli diversi.

10 · Il viaggio completo di un valore

Python / JS→nodo Source textBox→host gnr-textbox→input nativo

All’avvio Gramlot legge il binding, risolve il percorso e fornisce al componente il valore corrente. Il setter del componente lo porta sull’input. Quando l’utente modifica il testo, il percorso si percorre nell’altra direzione.

  1. L’utente scrive nell’input interno.
  2. Il componente espone il valore e gli eventi sul proprio host.
  3. L’ascoltatore delegato di Gramlot riconosce l’elemento e il nodo Source.
  4. La politica di aggiornamento decide se confermare adesso.
  5. Gli eventuali servizi di campo verificano il valore.
  6. Il valore confermato arriva nella Data Bag; i binding dipendenti si aggiornano.

Per impostazione predefinita il textBox conferma alla perdita del focus, dopo una modifica, attraverso l’evento change. Il testo digitato può quindi essere diverso dal dato già confermato. Con live=True si richiede l’aggiornamento durante la digitazione:

Python Esempio didattico
root.textBox(value='^nome', lbl='Nome', live=True)

Il parametro storico updateOn rimane un fallback; il codice attuale dà precedenza a live quando è specificato. “Live” regola la conferma dell’input, non crea il binding e non cambia il momento in cui Python viene eseguito.

Se un aggiornamento dell’attributo value arriva mentre l’input interno ha il focus, la base protegge il testo in corso di digitazione. Non va generalizzato a qualsiasi assegnazione: il setter pubblico scrive sul controllo. È importante distinguere il percorso usato dal runtime da una modifica diretta fatta da codice.

Nella Source Bag un textBox rimane un solo nodo. Label, contenitori e input del suo Shadow DOM non diventano figli Source. Una recipe, invece, compone più nodi Source: incapsulamento del componente e riuso della composizione sono concetti diversi.

default non è un comando “reimposta sempre”: un dato già presente non va cancellato dalla creazione di un altro campo. Per riutilizzare una composizione si passa un contenitore con un datapath, cioè un percorso di base:

Python Composizione riutilizzabile, non nuovo Web Component
def persona(parent, percorso):
    box = parent.div(datapath=percorso)
    box.textBox(value='^.nome', lbl='Nome')
    box.div('^.nome')

# Nel main di una pagina, dopo aver inizializzato i dati:
persona(root, 'cliente')
persona(root, 'fornitore')

Il punto iniziale in ^.nome rende il percorso relativo al contenitore. Le due istanze lavorano su dati diversi. Nessun accesso manuale agli input è necessario.

Per un’azione locale si modifica il dato attraverso Gramlot:

Python Esempio didattico
root.button('Imposta Ada', action="this.SET('nome', 'Ada');")

action contiene codice JavaScript eseguito nel browser; this è il nodo Source dell’azione. Il runtime offre anche il coordinatore gramlot, per esempio per pubblicare un messaggio. Il metodo Python non viene richiamato a ogni tasto.

12 · Null, errori e aspetto: servizi condivisi

Un input nativo mostra testo e non può rappresentare direttamente la differenza tra null e stringa vuota. La base usa InputNullState per conservarla. In Python il valore nullo è None; in JavaScript è null. Un campo vuoto a video non basta, da solo, a dire quale dato sia memorizzato.

La classe textBox non contiene un motore di validazione completo. FormField e Validator gestiscono bozza, verifiche e conferma secondo il contesto. Il mixin FieldState presenta il risultato: aria-invalid, aria-busy, messaggi e stile del campo. Questa divisione consente ad altri controlli di condividere le stesse regole.

Python Esempio didattico
root.textBox(value='^nome', lbl='Nome', validate_notnull=True)

La decorazione è gestita da WidgetLabel, non ripetuta nella sottoclasse textBox. L’etichetta reale è associata all’input interno con for="f" e id="f"; ciascuno Shadow DOM ha il proprio ambito. Il placeholder non sostituisce questa associazione.

Per l’aspetto, la base espone variabili CSS come --field-bg, --field-border e --field-focus-border. Si usano gli strumenti di stile Gramlot, senza cercare il controllo interno:

Python Esempio didattico
root.css('.accent-field', {
    '--field-border': '#397b83',
    '--field-focus-border': '#15575e'
})
root.textBox(value='^nome', lbl='Nome', class_='accent-field')

class_ è la forma Python del nome HTML class. La variabile CSS eredita il valore nell’interno del componente. Un cambiamento estetico non richiede una nuova classe Web Component.

13 · Dove intervenire quando vuoi cambiare qualcosa

ObiettivoPunto in cui operare
Un campo della tua pagina con etichetta diversaParametri di root.textBox
Più controlli riutilizzabili insiemeFunzione Python o recipe Gramlot
Una regola condivisa di conferma o validazioneServizio del framework responsabile, con test
Un comportamento specifico dell’editorClasse del componente, riusando le basi
Un nuovo componente dichiarabile da PythonImplementazione, registrazione e descrizione, quindi generazione e verifica

Per costruire un nuovo controllo sullo stesso modello: si sceglie l’elemento nativo, si espongono proprietà ed eventi, si riusano le capacità condivise, si registra il tag nel browser e si descrive il nome per Gramlot. Infine si verificano creazione, modifica dei dati, interazione, errori, rimozione e reinserimento.

Non si modifica direttamente src/gramlot/grammar/inputs.py: è un file generato. Non si copia tutta la base per ottenere una variante. Non si aggiunge un osservatore manuale della Data Bag dentro ogni campo se il binding è già responsabilità del runtime.

Controlla se il modello è chiaro: quattro domande

Chi riceve i tasti? L’input nativo nello Shadow DOM.

Chi collega il campo a persona.nome? Il runtime Gramlot attraverso il binding nel Source.

Dove sono label e input nell’inspector Source? Non sono nodi Source figli: sono l’implementazione interna del componente.

Per cambiare l’etichetta devo scrivere JavaScript? No: si passa lbl nella dichiarazione Python.
